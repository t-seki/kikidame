# Kikidame

English: [README.md](./README.md)

録り溜めた**ラジオ番組**を、Jellyfin サーバ・NAS の共有フォルダ（SMB）・端末のフォルダのどれかに置いている人向けの Android アプリ（ポッドキャストのファイルも使える）。番組単位のルールで各回を自動でダウンロード／削除し、取得元に届かなくても聴ける。既存の Jellyfin クライアントは映像か音楽が中心で、Kikidame は回が積み上がる音声の聴取に絞って作っている。

名前は「聴き溜め」から。放送された回を録り溜め、時間のあるときに手元で聴く、というアプリの用途そのものです。

## 入れ方

端末は Android 12 以上。Google Play では配布しない。

1. **GitHub Releases** — [Releases](https://github.com/t-seki/kikidame/releases) から `kikidame-<バージョン>.apk` を入れる
2. **Obtainium** — 自動更新したい人は [Obtainium](https://github.com/ImranR98/Obtainium) に `https://github.com/t-seki/kikidame` を登録する。更新は上書きで入り、手元の各回と再生位置は残る

IzzyOnDroid と F-Droid 本家には出していない。コードの大半を生成 AI（Claude Code）で書いていて、どちらもそれを受け付けないため。このプロジェクトでの生成 AI の扱いは [CONTRIBUTING.md](./CONTRIBUTING.md#日本語の要約)。

## 取得元

接続する取得元は同時に 1 つ。詳しい条件と、どこまで確かめたかは [docs/sources.md](./docs/sources.md)。

- **Jellyfin** — Jellyfin 10.10 以上。音声は**ブックのライブラリ**（コンテンツの種類「ブック」）か音楽ライブラリに入れる。勧めるのはブックのライブラリで、再生位置と再生済みを、同じ Jellyfin のユーザーでログインした Jellyfin Web やほかの端末とサーバを通して分け合う。音楽ライブラリ・NAS の共有フォルダ・端末のフォルダでは、再生位置と再生済みは手元だけで持つ
- **NAS の共有フォルダ（SMB）** — SMB2/3。ユーザー名とパスワードか、ゲストで接続する。アプリは共有を読むだけ
- **端末のフォルダ** — 内部ストレージか SD カードのフォルダを、Android のフォルダ選択で選ぶ。アプリはフォルダを読むだけ。コピーした回は端末の容量を二重に使う（フォルダのファイルと、アプリの中のコピー）。フォルダからファイルを消すと、次の同期でアプリの中のコピーも消えるので、ファイルは置いておく

ファイルのタグは `album` = 番組、`albumartist` = 配信元（ラジオなら放送局）、日付 = 公開日、`artist` = 出演者 にする。Jellyfin のライブラリでは、このタグで各回を番組にまとめる。NAS の共有フォルダと端末のフォルダは、ちょうど `<配信元>/<番組>/<各回のファイル>` の構成にする。配信元と番組はフォルダの名前で決め、タイトル・日付・出演者はタグから読む。ファイルが数千本ある NAS の最初の取り込みは十数分かかることがあり、終わるまでアプリを開いて画面をつけておく。

## できること

- **番組一覧** — 番組名・配信元名の検索と配信元での絞り込み。☆ を付けた番組（**よく聴く**）は別のタブにまとまる。取得元から無くなった番組には「取得元に見つかりません」と出る
- **同期** — 番組ごとに、同期するかと保持ルール（「最新 N 回まで保持」「再生済みなら削除」）を決める。同期は 3 時間ごと（「Wi-Fi のみ」も選べる）で、不足分を落とし余剰分を消す。取得元のファイルが書き換わったら（チャプターの書き足しなど）、同期が手元のファイルを差し替え、再生位置はそのまま
- **各回一覧** — ダウンロード・固定・再生済みの操作。**固定**した回（手動でダウンロードした回と、各回のシートの「固定する」で固定した回）は保持ルールでは消えない
- **オフライン優先** — 聴くのは常に手元のファイル。保持ルールで消すのは同期のときに、取得元の一覧を全部読めたときだけで、再生済みにした瞬間には消えない。取得元に届かなければ、同期は何も落とさず何も消さず、再生も止まらない
- **再生** — バックグラウンド再生と通知・ロック画面の操作、±10 秒、倍速（1.0〜2.0）、スリープタイマー、チャプター、続きから再開。末尾近く（残り 2 分）まで聴くと**再生済み**になり、同じ番組の次の回へ進む。Bluetooth の接続だけでは自動で再生しない。アプリを閉じた後も、ロック画面のメディアのコントロールに Kikidame のカードが残り、最後に聴いていた回を続きから聴ける
- **Android Auto** — 車の画面で「続きから」「よく聴く」「番組」をたどり、手元にある回を再生
- 英語と日本語の UI（Android 13 以上ならアプリごとに切り替え）と、テーマの 3 択

## 取得元を変える

設定で取得元を変えると、手元の番組・各回・再生位置・音声ファイルをすべて消してやり直す。同じ Jellyfin のサーバとユーザーのまま、ライブラリだけを選び直すのは取得元を変えることに当たらず、次の同期で番組と各回を結び直して残す。Jellyfin の音楽ライブラリからブックのライブラリへ移るときは、次の順に進める（手元の番組・各回・再生位置・再生済み・ファイルは、配信元・番組名・タイトルで結び直す）。

1. Kikidame を、ブックのライブラリを選べるバージョンに上げる
2. Jellyfin のダッシュボードで、音楽ライブラリを消す。同じフォルダを音楽とブックの 2 つのライブラリに入れると、アイテムが使い回され、ブックのライブラリでも音楽のまま見えるため
3. 同じフォルダで、コンテンツの種類が「ブック」のライブラリを作り、スキャンが終わるのを待つ
4. Kikidame の「設定」の「ライブラリ」をタップし、ブックのライブラリを選んで「決定」をタップする。同期が始まる
5. 番組・各回・聴きかけの回の位置・再生済みの印が残っていることを確かめる。結び直せなかった番組は手元に残り、設定の「取得元に見つからない番組を手元から消す」の数に入る

## やらないこと

- 映像・トランスコード・キャスト
- 複数のサーバ・ユーザー・ライブラリを同時に使うこと
- サーバ管理
- オーディオブック（古い章から順に聴くので「最新 N 回まで保持」が合わない）
- Google Play での配布

全体は [docs/architecture.md](./docs/architecture.md) の「やらないこと」。

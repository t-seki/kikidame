# UI の方針

#48（UI 全体の見直し）で決めた、アプリ全体の UI の方針。画面構成・動線・色・タイポグラフィの「何を大事にするか」と、画面ごとの役割を書く。用語は `CONTEXT.md` に従う（「お気に入り」「購読」「フォロー」など _Avoid_ に入っている語は UI のラベルに使わない）。

決定日: 2026-09-19。実装は sub-issue（#54〜#59）で行う。

## 大事にすること

1. **片手で「続き」か「未再生」をすぐ流せること。** 主な聴取シーンは寝る前・移動中で、腰を据えて番組を選ぶ時間は短い。操作は画面の下半分（親指が届く範囲）に寄せる
2. **学習コストを増やさないこと。** 番組 → 各回 → 再生 の 3 階層と、各画面の役割は変えない。動線の変更は「入口を減らす」方向だけ
3. **個性は構造ではなく色で出すこと。** dynamic color をやめ、固定パレットで「ラジオらしさ」を持たせる。構造を変えずに済むので実装コストが色・タイポの定義に閉じる
4. **手元／サーバの別、固定、消失は隠さないこと。** オフライン優先とフォルダ同期が差別化点なので、その状態は一覧の行に出したまま

## 色

固定パレット。ダークが主（寝る前の利用）で、ライトも同じ構成。既定は端末の設定に追従し、設定の「テーマ」で システム／ダーク／ライト を選べる（#62。「端末はライトのままアプリだけ常にダーク」のため）。

温かい黒（赤みのある黒）にアンバーのアクセント。状態を表す色は **`primary`（アンバー）と `error`（赤）の 2 系統だけ** にし、それ以外の意味を色に持たせない（聴いている回の行の背景だけ `secondaryContainer` で示す。タブの選択の表示は下の「共通の規則」）。

## タイポグラフィ

- 書体はシステムのまま（Material3 の既定 `Typography`）
- **数字は等幅（`tnum`）。** `未再生 3`・`1:23:45`・`12.3 GB` のように数が並ぶ場面が多いので、桁が揺れないようにする。全スタイルに付ける（#54）
- 再生画面の時間表示を大きくする案（後述の D 案）は採らない。色が入った後に実機で気になれば別 issue

### 共通の規則

- 番組の行（`ProgramRow`）と各回の行（`EpisodeRow`。各回一覧と「続きから」で共通）は、左右のアイコン・ボタンを行が何行でも上下の真ん中に置き、3 行でも 1〜2 行と同じ上下 8dp・最小 72dp にする（#157・#162。Material 3 の `ListItem` は補足が折り返すと 3 行の項目になり、左右が上寄せで上下 12dp・最小 88dp になる。そこから外すのは #157・#162 で決めたこと。`ListItem` をやめて `Row(verticalAlignment = CenterVertically)` で組む）
- 各回の行の再生位置のバーは、再生済みと未再生の間に隙間を空けない（`gapSize = 0.dp`。Material 3 1.4.0 の既定は隙間あり。隙間を無くす点だけミニプレイヤーの線（#59）と同じで、色・端の形・端の点は既定のまま。#162）
- 値を見せる行は `overlineContent` = ラベル、`headlineContent` = 値。操作の行は `headlineContent` = 操作名、`supportingContent` = 説明。少数の選択肢から 1 つ選ぶ行は `overlineContent` = ラベル、`headlineContent` = `FilterChip` の並び（保持ルールの「最新 N 回」、設定の「テーマ」）
- 状態の色は `primary`（よく聴く・同期対象・再生中）と `error`（消失・失敗・破壊的操作）だけ。聴いている回の行の背景は `secondaryContainer`。ただしタブは例外で、選んでいるタブの文字と下線に `primary`、選んでいないタブの文字に `onSurfaceVariant` を使う（#155。`Tab` の既定は選んでいないタブも `primary` になる）
- 同期中の表示は 2 種類で、両方は出さない（ただし下のタグの件数の帯だけは例外）。利用者の操作（引っ張って更新、各回一覧の同期のシートを閉じたときの同期。#311）はクルクル（`PullToRefreshBox`）、裏の同期（定期・起動時）は番組の画面（タブの下）・各回一覧のトップバーの下に細い不確定のバーと「バックグラウンドで同期中…」（`ui/BackgroundSyncBar.kt`、#138）。裏の同期の最中に操作が来たらクルクルに切り替える（#134）。共有フォルダの全走査でタグを読んでいる間は、裏の同期でも操作による同期でも、番組の画面のタブの下に目盛りのあるバーと「タグを読み込み中 1,234 / 6,090」（読み終えた数 / タグを読む回の数）を出す（#209）。操作による同期では、クルクルとこの件数の帯を重ねて出す（「両方は出さない」の例外。件数は裏でも操作でも見せたいため）。タグを読む回が無い同期（2 回目以降で変化が無いとき）では出さない。各回一覧には出さない
- 同期の完了・失敗の伝え方（#346）。手動の同期の結果（変化・失敗・「Wi-Fi ではない」）はスナックバー（番組一覧・各回一覧を開いているときだけ）。裏の同期のスナックバーは変化があったときだけで、失敗は出さない（#142 のまま）。全走査の最後の試み（成功・失敗とその理由・「Wi-Fi ではない」の見送り）は手動でも裏でも記録し（1 番組の同期は記録しない）、設定の「最終同期」の行の補足に出す（最終同期より新しく、成功でないときだけ）。裏の同期の失敗が、最終同期から 24 時間以上続いたら Android の通知を 1 回出す（チャンネル「同期」、重要度は低。成功するまで出し直さず、全走査が成功すると手動でも裏でも消える。一度も成功していないとき・見送り・手動の失敗では出さない。押すと番組一覧を開く。通知が許可されていない端末では出さない）。同期中の表示（上の 2 種類とタグの件数の帯）は変えない
- ボトムシートは「その画面に留まったまま 1 つ選ぶ」ときに使い、スクロールする長い一覧は画面にする（#43 の判断）
- データにある画像は出す。無いときは何も置かない（代わりの絵・頭文字の枠・偽の波形で埋めない）（#264 で改めた。それまでは「ジャケット・波形など、データに無い視覚要素で埋めない」。出す画像は番組の画像（CONTEXT.md）で、出す場所は番組一覧の行と再生画面。#289 で各回一覧のトップバーとミニプレイヤーも足した。#283 で回の画像（CONTEXT.md。各回に埋め込まれた画像）も足した。再生画面・通知・ロック画面・Auto の再生中の表示では回の画像を優先し、無ければ番組の画像。ADR 0012）

### 文言の足し方（#104、ADR 0009）

UI の文言は英語と日本語の 2 言語で、OS の「アプリの言語」（Android 13+）で切り替わる。既定は英語（日英以外の端末には英語が出る）。

- 文言は `app/src/main/res/values/strings.xml`（英語、既定）と `values-ja/strings.xml`（日本語）の**両方**に足す。片方だけだと lint の `MissingTranslation` でビルドが落ちる。`values/` には英語だけでは文脈が分からないキー（書式引数の意味、どの画面のどこか、CONTEXT.md の用語）に翻訳者向けの短いコメント、書式引数は `%1$s` のように番号付き、数+単位（「3 回」「15 分」）は `<plurals>`
- キーは `<area>_<what>` の snake_case。area は `common` / `connect` / `source_pick` / `smb_connect` / `library_pick` / `program_list` / `episode_list` / `episode_details` / `player` / `settings` / `sync` / `playback` / `auto`。英語の用語は CONTEXT.md の英語名（Program / Episode / Publisher / Pinned / Starred / Played …）に揃える
- **文字列に解決するのは Composable だけ。** Composable では `stringResource` / `pluralStringResource`。Composable の外（ViewModel・`LibraryRefresher`・`NowPlaying`・`EpisodeDetails`）は `String` ではなく `text/UiText.kt` の `UiText`（`Res(R.string.x, args)` / `Plural(R.plurals.x, n)` / `Plain(サーバから来た名前)` / `Joined(parts, separator)`。型は Compose に依存せず、`ui/` の外から使える。#243）を返し、表示側で `.resolve()`（`LaunchedEffect` の中でスナックバーに渡すときは `.resolve(LocalContext.current)`）。`Context.getString` を Composable の外に書かない。例外は `PlaybackService` と、同期の失敗の通知を組み立てる `sync/SyncFailureNotifier.kt` の `AndroidSyncFailureNotifier`（#346）（通知・Android Auto にはプロセスの外へ `String` を渡すしかない。ADR 0009 の末尾の注記）
- 日付（`2026-08-02`）・尺（`1:02:03`）・容量（`12.3 MB`）の書式は言語に依らず固定。言語で変わるのは区切り（`common_list_separator`「、」/ ", "）と単位だけ
- テスト: `UiText` を返す関数は `assertEquals(UiText.Plural(R.plurals.sync_new_episodes, 5), actual)` の形で「どの文言がどの引数で選ばれたか」を比べる。並びや省略を見たいテスト（行の補足など）は Robolectric に `@Config(qualifiers = "ja")` を付け、`resolve(context)` した日本語で比べる
- 3 言語目を足すときは `values-<lang>/strings.xml` を置くだけ（`generateLocaleConfig = true` が OS の言語一覧に自動で載せる）。翻訳の受け入れ体制（Weblate 等）は需要が見えてから

## 検討の記録

5 つの案を、同じ 5 軸（① 行の情報密度、② 階層、③ 絞り込みの入口、④ 色、⑤ 再生画面の主役）の上に置いて比べた。画面イメージは HTML で描き（[claude.ai/artifact/DNLd8CXT26Jc5SjN86uGDP](https://claude.ai/artifact/DNLd8CXT26Jc5SjN86uGDP)、補助）、実機での `/prototype` は行っていない。

| 案 | 大事にすること | 捨てるもの |
| --- | --- | --- |
| **A 棚** | 今の 3 階層を磨く。絞り込みを 1 つの入口に | 個性（色を別に決めれば補える） |
| B 番組表 | 配信元を最上位に。配信元タブ・配信元ごとの色 | 「よく聴く」の節。配信元が 1 つの利用者には効かない。配信元名の表記ゆれで色が割れる |
| C 続きから | ボトムナビ「聴く｜番組」を足し、番組横断で続き → 未再生 | 3 階層の単純さ。下部が 2 段になる。#41 の行の一部を各回一覧へ戻す |
| **D 受信機** | 固定パレット（温かい黒＋アンバー）、等幅数字、大きな時間表示 | Material You との親和性 |
| E 一枚の紙 | 番組行をバッジだけに、再生画面を巨大なボタンだけに | #41・#45、一覧からの ★。毎晩使うスリープが 2 タップになる |

**選んだのは構造 A ＋ 色 D。** 主な聴取シーンが「片手で続きを流す」なので C か E に寄せる案もあったが、

- C はホームを足す分だけ下部（ミニプレイヤー＋ボトムナビ）が厚くなり、番組をまたいで流す機能が無い今は「聴く」タブの価値が半分になる
- E はスリープタイマーを隠すのが寝る前のシーンと逆行する

ので、構造は変えず（A）、片手の要件は再生画面の操作を下半分に寄せること（#57）で満たす。色は D で、D の再生画面（大きな時間表示・太いトラック）は採らない。ライトも用意する（ダーク主）。

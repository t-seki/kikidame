Jellyfin の音楽アイテムの resume 挙動はサーバ設定に左右され、長尺のラジオ録音の再生位置をサーバに預けると設定次第で位置が失われる。そのため `PlaybackState`（再生位置・再生済み）はローカルに行があればローカルが常に勝ち、サーバの `UserData` は再インストールや初回取得で行が存在しないときの初期値としてのみ読む。ローカルの変更は `syncedAt` が null のものだけをオンライン復帰時にサーバへ送る（一方向、衝突解決なし）。
- タイムスタンプで新しい方が勝つ（`updatedAt` vs サーバ `LastPlayedDate`）— 他端末・Web との併用には便利だが、端末時計のずれとサーバ側タイムスタンプの粒度に依存し「ローカル正」でなくなる。聴くのはこのアプリだけという前提で見送り
- サーバを完全に無視して送信のみ — 再インストール時に全位置を失うので見送り
- 他端末や Jellyfin Web で同じ回を聴き進めても、このアプリ側の位置には反映されない（ローカルに行がある限り）
- `PlaybackState` 行は手元のファイル（`LocalFile`）が保持ルールで削除されても残し、各回（`Episode`）と同じライフサイクル（サーバに存在する限り）で生存させる。これにより再生済みの回が再ダウンロードされて即削除される往復が起きず、「再生済みなら削除」が一貫する

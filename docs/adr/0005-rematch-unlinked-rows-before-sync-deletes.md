ADR 0001 は「再取り込みで孤児化した行をサーバ側の新しい ID へ突合するルールは M3 で別途決める」と先送りしていた。M3-b までの突合は**サーバ ID を持たない行**にしか働かず、再取り込みで**古いサーバ ID を持った行**は対象外だったため、番組ごと ID が変わればサーバの新しい番組が別の行として追加されて二重になり、各回だけ ID が変われば同期が「サーバの一覧から消えた」と判断して各回と再生位置を消していた。そのため突合の対象を**未結合**（サーバ ID を持たない、または持っているサーバ ID がサーバの完全な一覧に無い番組・各回）に広げ、**同期が削除を判断する前**に同じ処理の中で走らせる。キーは従来どおり（番組は放送局 + 番組名、各回はタイトルの完全一致、第二段として放送日 + 尺）で、双方 1 対 1 のときだけ結ぶ。結び直せなかった各回は本当にサーバから消えた回として削除に落ち、結び直せなかった番組は消失として判断保留に残る。
- **確度の閾値と利用者の確認 UI** — 「候補が複数なら結ばない」の一段だけにした。閾値付きの自動結合は誤結合すると再生位置が別の回に付く事故になり、確認 UI はこのアプリに他に無い画面を 1 つ増やす。1 対 1 で結べない行は残す（番組）か消える（各回）だけで、どちらも取り返せる（番組は手動削除、各回は落とし直し）
- **ファイルサイズや内容ハッシュをキーにする** — サーバは一覧にサイズを返さず（`MediaSources` を避けている）、ハッシュはファイルが要る。放送日 + 尺で足りる
- **古い行と新しい行を後からマージする** — 突合を `newPrograms` の挿入より前に走らせれば二重行は生まれないので、マージ（CONTEXT.md「突合」の _Avoid_）は要らない
- 1 番組だけの同期では番組一覧が無いので、番組そのものの結び直しはできない（404 なら消失のまま）。各回の結び直しはその番組の一覧が完全なので同じに行う
- 結果として、`Known` の番組内で各回の ID だけが変わった場合（M3-b の既知の制約）は、タイトルが一致する限り消えなくなる

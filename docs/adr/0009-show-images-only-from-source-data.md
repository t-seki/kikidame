画像は**データにあるときだけ出す**。無いときは何も置かない（代わりの絵・頭文字の枠・偽の波形で埋めない）。画像は 2 つに分ける。

- **番組の画像**（CONTEXT.md）は、同期（全走査と 1 番組の同期）のときに取得元から取り、アプリの領域にファイルで持つ。表示のときに取得元から読まない。共有フォルダでは番組のフォルダの `folder.jpg`、Jellyfin の音楽のライブラリではアルバムの Primary の画像（ブックのライブラリは ADR 0010 の決定 2）
- **回の画像**（CONTEXT.md）は、同期の走査では読まない。再生するときに、手元のファイルに埋め込まれた画像を読む

録音ツールの rajikura（t-seki/rajikura#68）は、番組のフォルダに `folder.jpg` を置き、各回の m4a に画像を埋め込む。この 2 つを出せるようにするための決定である。

## 決定

1. `docs/ui.md` の原則は「データにある画像は出す。無いときは何も置かない」。番組の画像を出す場所は、番組一覧の行（★ の右に 48dp の正方形）、各回一覧のトップバー（戻るボタンの右、番組名の左に 40dp の正方形）、ミニプレイヤー（行の左に 40dp の正方形。聴いている回の番組の画像）、再生画面（タイトルの上に正方形）。各回の行には出さない。再生画面・通知・ロック画面・Android Auto は、回の画像を優先し、無ければ番組の画像
2. 番組の画像は、変わったときだけ取り直す。判定の値（版）は、共有フォルダでは `folder.jpg` の大きさと更新日時、Jellyfin では Primary の ImageTag で、Room の番組の行に nullable の列で持つ（版 9）
   - `folder.jpg` が無くなった番組は画像なし（手元のファイルを消す）
   - 取得に失敗しても同期は止めず、前の画像を残す
   - 画像が 10 MiB を超えるときは読まず、画像なしとして扱う（手元に画像のファイルがあれば消す）。版は書き、同じ版を同期のたびに取り直さない。ファイルが変われば（版が変われば）取り直す。上限の値に根拠は無く、測っていない
   - 「Wi-Fi のみ」の設定は、同期の中で取るのでそのままかかる
   - 番組の行が消えたとき、取得元を変えてやり直すとき（ADR 0007 の決定 2）は、画像のファイルも消す（「この番組を削除」と「取得元を変える」はその場で消す。消せずに残ったファイルは、全走査の最後に、どの行からも指されていないものとして消す）
3. 共有フォルダで読むのは、番組のフォルダ（2 段目）の `folder.jpg` だけ。名前は rajikura の付け方に合わせ、`folder.png` などは読まない。ほかの音声でないファイルは無視する（ADR 0007 の決定 5 の例外）
4. 画像の読み込みは Coil（Apache-2.0。ADR 0005 の MPL-2.0 と両立する）。手元のファイルを非同期で読み、縮小・メモリのキャッシュも任せる

## 番組の画像を手元に持つ理由

- オフラインでも出すため
- 表示のたびに SMB の木を開かないため（共有フォルダの木は、呼び出しのたびに開いて閉じる）
- 2 つの取得元（Jellyfin と共有フォルダ）の後段を同じ形にするため

## 回の画像を走査で読まない理由

- タグの部分読みで読む量が増える。`getEmbeddedPicture` が部分読みの `MediaDataSource` で使えるか、読む量がどれだけ増えるかは確かめていない（未確認）
- 取り込み済みの回は、大きさと更新日時が同じならタグを読み直さない（`ScannedFiles` の判定）。走査で画像を読むことにすると、今ある回の画像を得るには読み直しの条件を変えるか、全部を読み直す必要がある
- 回ごとに画像の保存先と Room の列が要る
- rajikura の付け方では、回の画像はその回を保存した時点の番組の画像で、番組の画像とほぼ同じ。走査で読んで得るものが少ない

## 結果

- 取得元の境界（`SourceGateway`）に、番組の画像の中身を取る口（`fetchProgramImage`）がある。版は `SourceProgram.image` に載せ、取り直すかは取り込みの側が決める。口の形と置き場は `docs/claude-code-handoff.md` の「番組の画像」節
- 回の画像は、再生に入った回の分だけ手元のファイルから読み、長辺 512px 以下に縮めて Media3 の `artworkData` で通知・ロック画面・Auto・再生画面に渡す（外のプロセスへ公開する ContentProvider は足さない）
- 依存に Coil（`coil-compose`）が加わり、ライセンスの一覧（`aboutlibraries.json`）に載っている

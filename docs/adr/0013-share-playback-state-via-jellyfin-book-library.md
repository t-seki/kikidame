再生位置と再生済みを、Jellyfin の**ブック**のライブラリの UserData を通して、ほかの端末や Jellyfin Web と分け合う（**再生の共有**）。ADR 0002（ローカルが正）と ADR 0007（サーバへ送らない）を置き換える。音楽のライブラリと共有フォルダは、今どおり手元だけで持つ（#352 の grill の決定、人の了承 2026-10-27）。

きっかけは「PC でも Kikidame と同じように再生位置と再生済みを使いたい」という依頼（#351 の調査、#352）。音楽のライブラリの各回（`Audio`）は `SupportsPositionTicksResume` が偽で、Jellyfin Web などが再生を報告すると位置は 0 に戻され、再生済みは再生を始めた時点で立つ（Jellyfin `v10.11.11` の `UserDataManager.UpdatePlayState`・`SessionManager.OnPlaybackStart`）。そのため音楽のライブラリのままでは、Web で聴いた位置を分け合えない。ブックのライブラリの各回（`AudioBook`）は、サーバが位置を保つ。

## 決定

1. 再生の共有は、取得元が Jellyfin の**ブック**のライブラリのときだけ行う。Jellyfin の音楽のライブラリも引き続き取得元に選べるが、共有はせず、今どおり手元だけで持つ。README ではブックのライブラリを勧める
2. ブックのライブラリでは、各回は `AudioBook`、番組は各回の `Album` のタグ、配信元は `AlbumArtist` のタグで表す。番組の取得元 ID は `<AlbumArtist>/<Album>` の文字列にする。ブックのライブラリには `MusicAlbum` が作られず、各回が 1 本だけの番組には番組のフォルダ（`Folder`）も作られないため、番組をアイテムやフォルダで組まない。番組の画像は、番組のフォルダの画像があればそれを使い、無ければ出さない（ADR 0012）
3. Kikidame は各回の UserData を `POST /UserItems/{itemId}/UserData` で直接書く（再生の報告（Sessions）は使わない）。Kikidame の規則（末尾から 2 分で再生済み、5 分未満の位置も残す）がそのまま保存され、`LastPlayedDate` には手元の更新時刻を入れる
4. 衝突の規則: 各回ごとに「最後に見たサーバの値」を手元に持つ。同期のとき、サーバの値が最後に見た値から変わっていれば、ほかの誰かが書いたとみなしてサーバの値を採る。サーバが変わっておらず手元が変わっていれば、手元を送る。両方が変わっていれば、手元の更新時刻とサーバの `LastPlayedDate` の新しい方を採る。位置と再生済みは 1 組で扱う（手元で未再生に戻した回も、新しい方として扱われる）
5. 送る時機は、一時停止・停止・回の終わり・再生済みの手動切替のとき。送れなかった分は「未送信」として次の同期で送る。読む時機は、同期のたびと、回の再生を始める直前（一時停止からの再開を含む。短いタイムアウトで、失敗したら手元の値で鳴らす）。同期で読むとき、聴いている回だけは手元のままにする
6. ほかの端末や Web で再生済みになった回は、取り込んだ後の同期で、手元で聴いた回と同じく保持ルールの対象になる
7. 同じ Jellyfin サーバ・同じユーザーでライブラリだけを変えるのは、ADR 0010 の決定 2 の「取得元を変える」に当たらない。手元は消さず、同期で未結合になった番組・各回を突合で結び直す（ADR 0005）。音楽からブックへ移るときもこれで手元の再生位置と再生済みを引き継ぎ、結び直した各回の状態は「未送信」としてサーバへ書く
8. 共有できないとき（書き込みの失敗など）も手元の再生は止めない。設定の「最終同期」の近くに再生の共有の状態を 1 行出し、通知は出さない

## 確かめた事実

- 2026-10-27、Jellyfin 10.11.11 のコンテナ（ブックのライブラリ）に、本番の録音のファイル名とタグを写した無音のファイル 65 本と 30 分のファイル 2 本を入れて確かめた（#352 のコメント）
  - 日付の後ろが無い名前、`-1` などの付く名前、` 1400` などの付く名前のどれも、`AudioBook` として一覧に出た（一覧から外れたものは無かった）
  - 再生の報告では、5 分未満で止めた位置は 0 に戻り、10 分で止めた位置は残り、残り 5 分未満で止めると再生済みになって位置は 0 に戻った（サーバの `MinAudiobookResume`・`MaxAudiobookResume`、既定 5 分）
  - `POST /UserItems/{itemId}/UserData` で書いた 3 分の位置は 3 分のまま残り、続きの一覧（`/UserItems/Resume`）に出た
  - `/Items` の `albums=` の絞り込みは `AudioBook` には効かなかった（ライブラリの全件が返った）
- 同じパスを音楽とブックの 2 つのライブラリに入れると、アイテムは使い回され、ブックのライブラリにも `Audio` と `MusicAlbum` のまま見える（本番の 10.11.11 で、2 つのライブラリのアイテムの id が全件一致した）。移るときは音楽のライブラリを消してからブックのライブラリを作る
- 未確認: Jellyfin 10.10・12 でのブックのライブラリの挙動、Jellyfin Web の画面でのブックのライブラリの見え方、音楽向けのクライアント（Finamp など）がブックのライブラリを出せるか

## 退けた案

- **音楽のライブラリのまま、UserData に位置を書く（#351 の A2）** — 書けるが、Web などが同じ回を再生すると位置が 0 に戻される。「Web で同じ回を聴かない」前提は、Jellyfin を使う人の体験を損なうので採らない
- **音楽のライブラリのまま、DisplayPreferences の `CustomPrefs`（client を `kikidame` にする）に置く** — 2026-10-27 にコンテナで、書いて読み戻せること、別の client の再生の報告で消えないことを確かめた。ただし本来は表示の設定を置く場所で、Web で聴いた分は分け合えず、PC で続きを聴くには Kikidame の PC 版が要る
- **Jellyfin のサーバのプラグインを自作する** — 利用者にプラグインを入れてもらう必要があり、開発と保守も増える
- **ADR 0002 が退けた「新しい方が勝つ」をそのまま使う** — サーバの値を書くのは Kikidame だけでなく Web もあるので、時刻だけで比べると時計のずれが常に効く。変わったかどうかを先に見て、時刻は両方が変わったときにだけ使う

## 結果

- 共有フォルダ（SMB）の再生の共有と、PC で共有フォルダの取得元を聴くクライアントは、別の epic（#353）で扱う（ADR 0010 の決定 6「取得元には書き込まない」は、それまで変えない）
- Web で 5 分未満だけ聴いた位置は残らず、Web では残り 5 分で再生済みになる（サーバの設定の範囲）。Kikidame の再生済み（末尾から 2 分）とは閾値が違う
- Kikidame の再生は、Jellyfin のダッシュボードの再生中や再生回数には出ない
- 2026-10-29 #353（grill）: 共有フォルダの再生の共有と、PC で共有フォルダの取得元を聴くクライアントは、作らないことにした。ADR 0010 の決定 6（取得元には書き込まない）は変えない

共有フォルダ（CONTEXT.md。取得元にすることは ADR 0007）の中は、ちょうど `<配信元>/<番組>/<各回のファイル>` の 3 段とする。配信元と番組は**フォルダの名前**で決め、タグは使わない。

## 決定

1. 3 段目にある音声ファイル（拡張子で判定: m4a、mp3、aac、ogg、opus、flac、wav）だけを各回とする。それ以外（2 段目以下・4 段目以上のファイル、音声でないファイル）は黙って無視する
2. 例外として、番組のフォルダ（2 段目）の `folder.jpg` だけは、番組の画像（CONTEXT.md）として読む（ADR 0009）
3. 名前が `.`・`@`・`#` で始まるフォルダとファイル（NAS や OS が作るもの）は、どの段でも無視する
4. 取得元が端末のフォルダのときも 3 段のまま。深さを選ばせる仕組みは作らない

## 理由

番組と配信元を、フォルダの構成ではなくタグ（album = 番組、albumartist = 配信元）で決める案と、`<番組>/<各回のファイル>` の 2 段も認める案を比べ、どちらも採らなかった。

- 主な radiko の録音ツールでは、番組がファイル名にしか無い。radigo・rec_radiko_ts・radish は 1 つのフォルダに `<局 ID>_<日時>` のような名前で書き出し、タグを付けない（各ツールのソース）。Radikool は `<局コード>/<番組名>_<日付>.mp3` の形で書き出す（airshelf の要件書の観測と、既定の書式についての二次情報。既定の書式は未確認）。タグで決めても 2 段を認めても、これらの人は使えるようにならない
- タグの入れ方はツールごとに違い、決まった読み方では番組と配信元が取れない。らじれこは album に局を入れ（観測）、Radikool は局を genre に入れる（観測）。タグを優先すると、3 段で使えているらじれこの利用者の番組が局ごとにまとまってしまう
- 2 段を認めて使えるようになるのは、主に Podcast のダウンローダー（gPodder・Podgrab。どちらも `<Podcast 名>/<回>` の 2 段）の利用者で、主に想定する利用者（ラジオの録音を聴く人）から外れる

## 退けた案

- **タグ（album・albumartist）で番組と配信元を決める** — 上の 1 つ目と 2 つ目の理由
- **2 段（`<番組>/<各回のファイル>`）も認める** — 上の 1 つ目と 3 つ目の理由

2 段など別の構成を求める具体的な利用者やツールが現れたら、2 段を認める案から検討する。そのときは、番組とフォルダが 1 対 1 であることに、全走査だけでなく 1 番組の同期、取得元 ID（ADR 0007 の決定 7）、番組の画像（ADR 0009）も依存していることを前提に入れる。

番組・各回・手元のファイル・再生位置の同一性は、取得元 ID（Jellyfin の id、共有フォルダでは中の相対パス。ADR 0007）に直結させない。手元の主キーは代理キーとし、取得元 ID は nullable な一意の値として持つ（列の形は `docs/architecture/schema.md` の「Room スキーマ」）。取得元 ID を持たない行、持っている取得元 ID が取得元の完全な一覧に無い行（**未結合**）は、正規の状態として存在できる。

未結合の行は、**同期が削除を判断する前**に、同じ処理の中で取得元の行へ**突合**して結び直す。キーは、番組は配信元 + 番組名、各回は同じ番組の中のタイトルの完全一致で、第二段として公開日 + 尺を使う。番組・各回とも、双方が 1 対 1 のときだけ結ぶ。結び直せなかった各回は本当に取得元から消えた回として削除に落ち、結び直せなかった番組は消失として判断保留に残る。

## 理由

- 取得元 ID を主キーにすると、サーバ側のライブラリの再取り込み（フォルダの移動・DB の作り直し）や共有フォルダでのファイル名の変更で ID が変わった瞬間に、手元のファイルと再生位置がすべて孤児になる。「取得元に到達できなくてもアプリが成り立つ」というオフライン優先の前提が崩れる
- 代理キーで行を守っても、同期が「取得元の一覧に無い = 削除」を無条件に適用すれば同じ結果になる。そのため同期の入力は番組ごとに `Known / Unavailable / Gone` の 3 状態を持ち、`Gone`（番組の取得元 ID が取得元の番組一覧に無い）は判断保留とし、「一覧に無い各回を削除」は `Known` の番組に属する、取得元 ID を持つ各回にだけ適用する（削除の権限は ADR 0003）
- 突合の対象を取得元 ID を持たない行だけにすると、古い取得元 ID を持った行が対象から外れる。番組ごと ID が変われば取得元の新しい番組が別の行として加わって二重になり、各回だけ ID が変われば同期が「一覧から消えた」と判断して各回と再生位置を消す。未結合に広げ、削除の判断より前に走らせると、1 対 1 で結べる限りどちらも起きない
- 突合を新しい番組の挿入より前に走らせれば、1 対 1 で結べる限り二重の行は生まれないので、古い行と新しい行を後からまとめる処理（CONTEXT.md「突合」の _Avoid_）は要らない

## 退けた案

- **取得元 ID を主キーにし、再取り込みは起きないものとして運用で避ける** — スキーマは単純だが、起きたときの被害（全削除と再生位置の消失）が大きすぎる
- **確度の閾値と利用者の確認 UI** — 閾値付きの自動結合は、誤って結ぶと再生位置が別の回に付く。確認 UI は、このアプリにほかに無い画面を 1 つ増やす。1 対 1 で結べない行は残る（番組）か消える（各回）だけで、どちらも取り返せる（番組は手で削除、各回は落とし直し）ので、「候補が複数なら結ばない」の一段だけにした
- **ファイルの大きさや中身のハッシュをキーにする** — Jellyfin は一覧に大きさを返さず（`MediaSources` を求めない）、ハッシュにはファイルが要る。公開日 + 尺で足りる

## 結果

- 結び直せなかった番組（同名が複数など）は、古い行が消失として残り、新しい行が別に立つ。古い行は手で削除して取り返す
- 1 番組だけの同期では番組一覧が無いので、番組そのものの結び直しはしない（番組が取得元に無ければ消失のまま）。各回の結び直しは、その番組の一覧が完全なので同じに行う
- `Known` の番組の中で各回の ID だけが変わっても、タイトルが一致する限り各回は消えない
- Jellyfin のライブラリだけを選び直したときの結び直しも、この突合で行う（選び直しの扱いは ADR 0010 の決定 7）

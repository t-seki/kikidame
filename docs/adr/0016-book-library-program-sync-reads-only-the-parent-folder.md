Jellyfin のブックのライブラリの 1 番組の同期は、ライブラリ全体（AudioBook 全件と Folder 全件）を取らずに、手元が知っているその番組の各回の親フォルダの直下だけを取り、タグで番組に選び直す。絞り込みの結果を完全な一覧とみなせないときは、ライブラリ全体の取得に切り替えて削除を判断する。

## 決定

1. **取り方。** 番組のフォルダが有る番組も、各回が 1 本だけの番組も、同じ手順で取る（別の分岐を持たない）
   1. 手元が知っているその番組の各回の取得元 ID（取り込み日時の新しい順に渡る）のうち、先頭の 3 本を `ids=` で引き、今の `ParentId` を得る
   2. `parentId=<その ParentId>&recursive=false&includeItemTypes=AudioBook` で親の直下の各回を取る。`userId` と `enableUserData` を付け、`Fields` はライブラリ全体の取得と同じ（`DateCreated,ParentId,Path,Etag,DateLastSaved`）
   3. 返った各回を、Album と AlbumArtist のタグで番組に選び直し（ライブラリ全体の取得と同じ判定、ADR 0010 の決定 2）、その応答から各回を作る（ライブラリ全体の取得と同じ変換）。再生の共有（ADR 0010）の UserData（再生位置・再生済み・`LastPlayedDate`）と各回の版（`Etag`、ADR 0011）は、全件の取得と同じに読める。各回が 1 本だけの番組の親は配信元のフォルダで、その直下にはほかの番組のフォルダも並ぶが、タグで選び直すので混ざらない
2. **削除の権限との関係（ADR 0003）。** 1 番組の同期の削除の権限は、その番組の完全な一覧だけが持つ。絞り込みの結果は、手元が知っている各回が全部載っているときだけ、その番組の完全な一覧とみなす。そうでなければ、ライブラリ全体を取って、その中からその番組の一覧を作り（今までの取り方）、それで削除を判断する。切り替えたライブラリ全体の一覧にその番組が無いとき、手元から既知の各回を渡しているなら、1 番組の同期の失敗として扱う（例外を投げ、今回は何も消さず、次の同期で取り直す）。走査の途中（親フォルダの付け替わり）でたまたま一覧から外れただけのことがあるため。この場合、1 番組の同期は番組の消失（`Gone`）を返さない。サーバで本当に番組が消えたときの手元からの削除は、ライブラリ全体の同期で扱う。既知の各回が無ければ、今までどおり全件の一覧に無い番組を消失とする
3. **安全網。** 次のどれかのときは、ライブラリ全体の取得に切り替え、切り替えた理由をログに残す。判定は SDK の呼び出しから切り離した関数（`BookProgramNarrowing`）にし、実サーバの無いテストで確かめる
   - 手元に取得元 ID のある各回が 0 本で、親を引けない
   - `ids=` で引いた既知の各回が、サーバに無い
   - 既知の各回が、絞り込みの結果に 1 本でも載らない。`ids=` で引いた各回の親が複数に分かれている（親が無い）ときも、これに含める
4. **番組の画像。** 親を `ids=<親>` で 1 件引き、その名前が Album と同じときだけ、その Primary の画像の版を番組の画像にする（ライブラリ全体の取得と同じ規則。違えば画像なし、ADR 0009）。画像の中身を取るための番組 → 番組のフォルダの覚えも、この経路で、ほかの番組の覚えを残したまま埋める
5. **サポートするバージョンは変えない。** Jellyfin 10.10 以上のまま
6. **版（`Etag`）をそろえる欄。** ブックの各回の取得（ライブラリ全体の取得と、親の直下の取得）の `Fields` に `DateLastSaved` を入れる。Jellyfin 10.10.7 では、入れないと、親の直下の取得（`parentId=&recursive=false`）だけが、同じ各回にライブラリ全体の取得や `ids=` の取得と違う `Etag` を返した。入れると、10.10.7 / 10.11.11 / 12.0.0 のどれでも、全件の一覧・親の直下・`ids=` の版がそろう（同じ問い合わせを繰り返しても変わらない。`DateLastSaved` の値そのものは応答に入らない）。版が取り方で違うと、1 番組の同期と全走査のたびに各回が変わったと見なされる。そろうので、選び直した各回を `ids=` で引き直すことはしない（以前は 100 件ずつ引き直していたが、各回の多い番組で 1 番組の同期が遅くなった）
   - 10.10.7 では、`DateLastSaved` を入れると、ライブラリ全体の取得が返す版の値が一度だけ変わる（10.11.11 と 12.0.0 では変わらない）。手元に落とした回は、次の同期で版が変わったと見え、差し替えの確かめ（ADR 0011）が 1 回ずつ走る。これは受け入れる

## 理由

ライブラリ全体の取得は、全件を 500 件ずつ取ってまとめるので、ライブラリが大きいと 1 番組の同期が重い（番組を開いたときの同期で、実機で約 15 秒）。各回の親の直下だけなら、その番組（と同じ配信元のフォルダに並ぶ各回）の数だけで済む。

既知の各回の親を引くのは、ブックのライブラリに番組のアイテムが無く、番組の取得元 ID（`<AlbumArtist>/<Album>`）からは場所が引けないため。新しい側の各回を引くのは、走査の途中で親が付け替わるとき（各回が 1 本だけの番組に 2 本目が足されたときなど）でも、新しい回ほど今の場所を指していると見込めるため。付け替わりの途中で各回の親が分かれていれば、安全網でライブラリ全体に切り替わる。

## 退けた案

- **`albums=` による絞り込み** — `AudioBook` に効かない Jellyfin がある。Jellyfin 10.10.7 では効き、Jellyfin 12.0.0 では 0 件、Jellyfin 10.11.11 では全件が返った。0 件が返る版で削除を判断すると、各回を誤って消す
- **Folder の名前による引き当て** — 各回が 1 本だけの番組は番組のフォルダが無く（親が配信元のフォルダ）、名前の重なりでほかの番組のフォルダに当たりうる
- **番組のフォルダ id の DB への保存** — 走査で親が付け替わると古い id が残る。毎回、既知の各回から今の親を引けば足りる
- **取得結果の使い回し（短時間のキャッシュ）** — 古い一覧で削除を判断しない（ADR 0003）

UI の文言は `res/values*/strings.xml` に置き、**文字列に解決するのは Compose だけ**にする。Composable の外で文言を作る場所（同期の結果のスナックバー、聴いている回の通知、画面の状態のエラー、各回の詳細の行のラベル）は `String` ではなく、文言の識別子と引数を持つ型 `UiText` を返し、表示する Composable が解決する。`Context.getString` は UI の外に書かない。型と解決の仕組みは `docs/architecture/i18n.md` の「UI の文言（i18n）」節。

例外は、プロセスの外（システムの UI・車載機）へ `String` を渡すしかない次の 2 か所で、そこでは `getString` する。

- 再生サービス: 通知のボタン名と Android Auto のブラウズツリー
- 同期の失敗の通知: 通知を組み立てる 1 か所で `getString` し、そこまでは `UiText` で持つ

## 退けた案

- **`@ApplicationContext Context` を ViewModel・同期の実行側・再生サービスに注入して、`getString` した `String` を流す** — `Flow<String>` の型を変えずに済むが、下の「理由」の 3 点で見送った

## 理由

上の退けた案と比べて、`UiText` を返す形を採った理由。

1. テストが文言の比較になり Robolectric が要る。`UiText` なら「どのメッセージがどの引数で選ばれたか」を値の比較で確かめられ、素の JVM で済む。並び・省略の規則を見るテスト（行の補足 2 つと各回の詳細）だけは、Robolectric で日本語に解決した文字列で比べる
2. 保持されている `uiState.error` が言語の切り替えに追従しない
3. プロセスの中で Service・Worker・UI が共有する `NowPlaying`（ADR 0004）に Android の `Context` が入る

## 言語

- 既定のロケールは英語。日英以外の端末には既定が出るので、英語の説明文を読んで入れた人に日本語を出さない。文字列を足すときは両方の言語に足し、片方の言語にしか無い文字列は lint のエラーにして防ぐ
- 言語の切り替えは OS の「アプリの言語」（Android 13+）だけ。アプリの中の切り替えは AppCompat を足すことになるので置かない。Android 12 はシステムの言語に従う
- 翻訳の受け入れの仕組み（Weblate など）は、需要が見えてから用意する。言語ごとの文字列ファイルが唯一の入口である形だけを守る
- 日付・時刻・尺・容量の書式（`2026-08-02`、`08-02`、`1:02:03`、`12.3 MB`）はロケールによらず固定。資源にするのは日本語の句読点と単位（「、」区切り、「（123 回）」）だけで、数 + 単位は複数形の資源にする

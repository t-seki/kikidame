画像は**データにあるときだけ出す**。無いときは何も置かない（代わりの絵・頭文字の枠・偽の波形で埋めない）。画像は 2 つに分ける（#264 の grill の決定、人の了承 2026-10-12）。

- **番組の画像**（CONTEXT.md）は、同期（全走査と 1 番組の同期）のときに取得元から取り、アプリの領域にファイルで持つ。表示のときに取得元から読まない。共有フォルダでは番組のフォルダの `folder.jpg`、Jellyfin ではアルバムの Primary の画像（#282）
- **回の画像**（CONTEXT.md）は、同期の走査では読まない。再生するときに手元のファイルから読む（#283）

きっかけは t-seki/rajikura#68（PR t-seki/rajikura#71、2026-10-12 マージ）で、rajikura が番組のフォルダに `folder.jpg` を置き、各回の m4a に画像を埋め込むようになったこと。それまで `docs/ui.md` の共通の規則は「ジャケット・波形など、データに無い視覚要素で埋めない」で、画像を扱う実装も画像の読み込みのライブラリも無かった（#264 の「確かめた事実」）。

## 決定

1. `docs/ui.md` の原則を「データにある画像は出す。無いときは何も置かない」に改める。出す場所は番組一覧の行（★ の右に 48dp の正方形）と再生画面（タイトルの上に正方形）。各回一覧とミニプレイヤーには出さない（実機で見てから足すかを決める）。再生画面・通知・ロック画面・Auto は、回の画像を優先し、無ければ番組の画像（#283。#264 の時点の再生画面は番組の画像だけ）
2. 番組の画像は、変わったときだけ取り直す。判定の値（版）は、共有フォルダでは `folder.jpg` の大きさと更新日時、Jellyfin では ImageTag（#282）で、Room の番組の行に nullable の列で持つ（版 9）
   - `folder.jpg` が無くなった番組は画像なし（手元のファイルを消す）
   - 取得に失敗しても同期は止めず、前の画像を残す
   - 共有フォルダの `folder.jpg` が 10 MiB を超えるときは読まず、画像なしとして扱う（手元に画像のファイルがあれば消す）。版は書き、同じファイルを同期のたびに取り直さない。ファイルが変われば（版が変われば）取り直す（PR #288 1 周目 #5 で人が決めた。上限の値に根拠は無く、測っていない）
   - Wi-Fi のみの設定は、同期の中で取るのでそのまま掛かる
   - 番組の行が消えたとき、取得元を変えてやり直すとき（ADR 0010 の決定 2）は、画像のファイルも消す（「この番組を削除」と「取得元を変える」はその場で消す。消せずに残ったファイルは、全走査の最後に、どの行からも指されていないものとして消す）
3. 共有フォルダで読むのは、番組のフォルダ（2 段目）の `folder.jpg` だけ。名前は rajikura の付け方に合わせ、`folder.png` などは読まない。ほかの音声でないファイルは今までどおり無視する（ADR 0010 の決定 5 の例外。ADR 0010 の末尾に注記した）
4. 画像の読み込みは Coil（Apache-2.0。ADR 0008 の MPL-2.0 と両立する）。手元のファイルを非同期で読み、縮小・メモリのキャッシュも任せる

## 番組の画像を手元に持つ理由

- オフラインでも出すため
- 表示のたびに SMB の木を開かないため（共有フォルダの木は、呼び出しのたびに開いて閉じる）
- 2 つの取得元（Jellyfin と共有フォルダ）の後段を同じ形にするため

## 回の画像を走査で読まない理由

- タグの部分読みで読む量が増える。`getEmbeddedPicture` が部分読みの `MediaDataSource` で使えるか、読む量がどれだけ増えるかは確かめていない（未確認。#264 の背景）
- 取り込み済みの回は、大きさと更新日時が同じならタグを読み直さない（`ScannedFiles` の判定、#197）。走査で画像を読むことにすると、今ある回の画像を得るには読み直しの条件を変えるか、全部を読み直す必要がある
- 回ごとに画像の保存先と Room の列が要る
- rajikura の付け方では、回の画像はその回を保存した時点の番組の画像で（t-seki/rajikura#68、#264 の背景）、番組の画像とほぼ同じ。走査で読んで得るものが少ない

## 結果

- #264 で、共有フォルダの番組の画像と、番組一覧の行・再生画面の表示を入れた。Jellyfin の番組の画像の取得は #282、回の画像と再生まわり（通知・ロック画面・Auto）は #283
- 取得元の境界（`SourceGateway`）に、番組の画像の中身を取る口（`fetchProgramImage`）を足した。版は `SourceProgram.image` に載せ、取り直すかは取り込みの側が決める。口の形と置き場は `docs/claude-code-handoff.md` の「番組の画像」節
- 依存に Coil（`coil-compose`）が加わった。ライセンスの一覧（`aboutlibraries.json`）を作り直した
- 2026-10-12 #282: Jellyfin はアルバムの Primary の画像を取り、版は Primary の ImageTag。共有フォルダと同じ 10 MiB の上限を掛け、超えたら画像なしとして扱う（手元のファイルは消し、版は書いて同じ版を取り直さない。PR #293 の 1 周目 #3 で人が決めた。上限の値に根拠は無く、測っていない）
- 2026-10-12 #289: 決定 1 の「各回一覧とミニプレイヤーには出さない」を改め、各回一覧のトップバー（戻るボタンの右、番組名の左に 40dp の正方形）とミニプレイヤー（行の左に 40dp の正方形。聴いている回の番組の画像）にも番組の画像を出す（PR #288 の実機確認で人が決めた。各回の行には出さない。決定の核は変わらない）
- 2026-10-12 #283: 回の画像は走査では読まず再生に入った回の分だけ手元のファイルから読み、長辺 512px 以下に縮めて Media3 の `artworkData` で通知・ロック画面・Auto・再生画面に渡す（外のプロセスへ公開する ContentProvider は足さない。回の画像が無ければ番組の画像）

アプリはオープンソースとして公開し（ライセンスは ADR 0012）、Google Play を通さず、**GitHub Releases** の署名済みの APK と、Releases を追って更新を知らせる **Obtainium** で無償で配る。IzzyOnDroid と F-Droid 本家には申請しない。

## Play を通さない理由

有料化（Play でクローズドソースの買い切り + 機能を制限した無料のアプリ）も検討したが、対象となる利用者（Jellyfin を自宅で運用し、番組型の音声を聴く人）の規模では年数万円程度の見込みで、Play の要件 — 個人アカウントで課金するなら住所の全公開、公開前に 12 人のテスターを 14 日間続けて確保、審査のたびにインターネットから到達できるデモ用の Jellyfin サーバを用意、確定申告 — に見合わないと判断した。オープンにすることで `jellyfin-sdk-kotlin`（LGPL-3.0）をそのまま使え、クローズドにするときに要る自前の HTTP クライアントへの差し替えも要らない。

## IzzyOnDroid と F-Droid 本家に申請しない理由

README の「入れ方」と同じ 2 つ。

1. どちらも、生成 AI で書かれたコードを含むアプリを受け付けない方針である（IzzyOnDroid の App Inclusion Policy）。Kikidame のコードは大半を Claude Code で書いており、正直に申告すれば却下の対象になる。虚偽の申告はしない
2. F-Droid 本家はソースからビルドし直して F-Droid の鍵で署名するため、Releases の APK とは署名が違い、片方からもう片方へ更新できない

## そのほかの決定

- 名前とアプリ ID は Jellyfin のブランディングの方針（第三者のアプリは名前に Jellyfin を使えず、Jelly〜 / 〜fin も勧められない、ロゴは使えない）に従う。これは配布の経路によらず要る
- 有料化の選択肢は残す。需要が見えたら、Releases は無料のまま Play に有料のアプリ（開発の支援）を加える「併売」に進み、そのときに Play の要件を満たしに行く。クローズドには戻さない
- iOS のアプリを作るときは、`jellyfin-sdk-kotlin` が JVM/Android 専用なので、そこで初めて KMP に対応した HTTP クライアントに置き換える。Android だけのうちは置き換えない

## 退けた案

- **Play でクローズドソースの買い切り + 無料のアプリ** — 収益は出るが、上の要件と費用対効果で見送った。LGPL のため SDK の差し替えも要る
- **オープンソース + Play で有料のバイナリ** — LGPL の問題は無いが、対象の層はビルドできる人で「ビルドすれば無料」と相性が悪く、Play の要件は全部かかる。併売に進むときの形として残す
- **Limited Distribution（無料・身分証不要・20 台まで）で身内に配る** — 公に配らないなら足りる。公開を選んだので採らない
- **IzzyOnDroid と F-Droid 本家で配る** — 上の 2 つの理由で申請しない

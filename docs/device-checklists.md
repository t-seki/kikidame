### 実機チェックリスト（#355: 再生の共有）

取得元が Jellyfin のブックのライブラリのとき、再生位置と再生済みを UserData で分け合うようにした（ADR 0013 の決定 3〜6・8）。書き込みと読み戻しは 10.10.7・12.0.0 のコンテナの統合テストで確かめたが、PR の時点では、どれも実機で見ていない（未確認）。確かめるのは人。本番 10.11 で確かめるときは、Kikidame と Jellyfin Web で同じ Jellyfin のユーザーでログインする。

- [ ] Kikidame で途中まで聴いて一時停止した回の位置が、Jellyfin Web の同じ回の「続きから」に出る。再生済みにした回は Web でも再生済みになり、未再生に戻すと Web でも未再生に戻る
- [ ] Jellyfin Web で途中まで聴いた回（5 分以上）の位置が、Kikidame の全体の同期（番組一覧を引っ張って更新）の後に各回一覧の位置に出る。Web で聴き終えた回は再生済みになる
- [ ] 同じく、その番組の 1 番組の同期（各回一覧を引っ張って更新）の後にも、各回一覧の位置に出る
- [ ] Jellyfin Web で途中まで聴いた回を、Kikidame で同期せずに ▶ すると、Web で止めた位置から鳴る（一時停止から再開したときも同じ）。鳴り始めの待ちが長すぎない（2 秒まで）
- [ ] 通知・ロック画面の ▶、Android Auto の ▶、Bluetooth ヘッドセットのメディアボタンの ▶ でも、Web で止めた位置へ移ってから鳴る（一時停止から再開したときも同じ）
- [ ] 番組の次の回へ移ったとき（聴き終えて自動で移る・⏭／⏮）、Web で途中まで聴いていた回なら、その位置へ移る
- [ ] 聴いている回（一時停止中を含む）は、同期の後も位置が飛ばない
- [ ] 機内モードで途中まで聴いて一時停止し、設定の「再生の共有」に送れなかったことが出る（`error` の色）。機内モードを戻して同期すると、その位置が Web に出て、設定の補足の行が消える
- [ ] 機内モードで ▶ を押しても、2 秒ほどで手元の位置から鳴る
- [ ] 「再生済みなら削除」の番組で、Web で聴き終えた回が、次の同期で手元から消える
- [ ] 音楽ライブラリでは、設定に「再生の共有」の行が出ず、Kikidame で聴いた位置が Web に出ない
- [ ] 音楽ライブラリからブックのライブラリへ移った後の同期で、手元の聴きかけの位置と再生済みが Web に出る
- [ ] #354 の版（ブックのライブラリを選べるが共有しない版）でブックのライブラリを使っていた端末を、この版に上げた後の最初の同期で、手元の聴きかけの位置と再生済みが Web に出る。上げる前に Web の方で後から聴き進めていた回は、Web の値が残り、Kikidame にもその位置が入る
- [ ] 再生を止めて通知を消し、再生のサービスが終わっても、アプリが落ちない（もう一度開いて再生できる）
- [ ] Jellyfin のダッシュボードの「再生中」に Kikidame の再生が出ない
- [ ] 英語（アプリの言語を English）でも、設定の「再生の共有」の行の文言が崩れない

### 実機チェックリスト（#358: ▶ の読み込み中に出力先が外れたとき）

▶ の直前の読み込みを待っている間に出力先が外れたら（Bluetooth が切れるなど）、待っていた ▶ を取り消して鳴らさない。取り消さないと、読み込みが打ち切られた後にスピーカーで鳴り始めることを、#358 の issue のコメントで実機で確かめた。この取り消しの実機での確認は未確認。確かめるのは人。

- [ ] Bluetooth で聴いている端末で、Jellyfin のブックのライブラリのダウンロード済みの回を一時停止し、Jellyfin のコンテナを凍らせて（ノードで `k3s ctr -n k8s.io task pause`）から通知の ▶ を押し、すぐに Bluetooth を切る。スピーカーでは鳴らず、一時停止のままになる（通知・ミニプレイヤーの表示も一時停止）。コンテナを戻して改めて ▶ を押すと普通に鳴る
